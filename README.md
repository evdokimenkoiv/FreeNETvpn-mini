# FreeNETvpn-mini

Упрощённая версия [FreeNETvpn](https://github.com/evdokimenkoiv/FreeNETvpn): только **WireGuard** и **VLESS REALITY**, полностью автоматическая настройка и установка одной командой.

В mini-версии нет Docker, Caddy, IKEv2, L2TP, Outline, AmneziaWG, MTProto и дополнительных прокси. WireGuard, Xray и лёгкая панель управления работают непосредственно как systemd-сервисы. При установке создаются один WireGuard-пир `client1`, один VLESS-пользователь и пароль администратора панели; домен и TLS-сертификат не нужны.

## Требования и минимальные ресурсы

- Чистая **Ubuntu 22.04/24.04/26.04 LTS x86_64**, systemd, root/sudo и публичный IPv4.
- На провайдерском firewall открыть **UDP 51820** и **TCP 443** (либо значения `WG_PORT`/`VLESS_PORT`).
- SSH-порт сохраняется в правилах UFW. UDP/TCP-порты не должны перехватываться HTTP-прокси.

| Ресурс | Минимум | Рекомендуется |
|---|---:|---:|
| Свободное место на `/` перед установкой | **1 ГиБ** — проверяется установщиком | **2 ГиБ и больше** |
| Общий размер диска VPS | **8 ГиБ** для минимальной Ubuntu | **10–20 ГиБ** |
| RAM | **512 МиБ** | **1 ГиБ** |
| CPU | **1 vCPU** | 1 vCPU |

Сам mini-проект ориентировочно добавляет **150–350 МиБ** к базовой системе: Xray, WireGuard tools, зависимости и APT-метаданные. Точный результат зависит от уже установленных пакетов и состояния APT. Временные архивы установщик удаляет. Основной расход диска обычно даёт сама Ubuntu, её обновления и журналы, а не VPN.

Для VPS с 512 МиБ RAM желательно заранее включить swap на 512 МиБ–1 ГиБ, чтобы APT не завершался по OOM. После установки сервисы потребляют заметно меньше памяти, чем полный проект: нет Docker daemon, containerd и дополнительных контейнеров. Панель использует только стандартную библиотеку Python и не требует базы данных.

## Установка одной командой

```bash
sudo bash -c 'set -e; apt-get update -qq; apt-get install -y --no-install-recommends ca-certificates curl; f=$(mktemp); trap "rm -f -- \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/evdokimenkoiv/FreeNETvpn-mini/main/install.sh -o "$f"; bash "$f"'
```

Установщик:

1. определяет публичный IPv4 (можно задать `SERVER_HOST` вручную);
2. устанавливает только необходимые пакеты и закреплённый Xray `26.3.27`;
3. проверяет ZIP Xray по SHA-256 из официального `.dgst` релиза;
4. генерирует постоянные ключи WireGuard и REALITY, UUID, short ID и PBKDF2-хеш пароля панели;
5. настраивает IP forwarding, NAT, UFW и три systemd-сервиса;
6. проверяет конфигурацию Xray, состояние VPN и авторизацию панели;
7. выводит готовую VLESS-ссылку, путь к WireGuard-профилю и одноразовый пароль панели.

Если автоматическое определение адреса не подходит, перед той же командой задайте DNS-имя или IPv4:

```bash
sudo SERVER_HOST=vpn.example.com bash -c 'set -e; apt-get update -qq; apt-get install -y --no-install-recommends ca-certificates curl; f=$(mktemp); trap "rm -f -- \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/evdokimenkoiv/FreeNETvpn-mini/main/install.sh -o "$f"; bash "$f"'
```

Проект устанавливается в `/opt/freenetvpn-mini`. Повторный запуск не пересоздаёт ключи, клиентов и пароль панели. Если UFW управляется отдельно, в скачанном проекте используйте `sudo bash install.sh --no-firewall`.

## Данные для подключения

Самый простой способ получить подключения — открыть панель по инструкции ниже. В разделе **«Клиенты и подключения»** можно создавать профили, скачивать WireGuard-конфиги и VLESS JSON, копировать VLESS-ссылки, перевыпускать ключи и удалять клиентов.

Через SSH на сервере оба профиля выводятся одной командой:

```bash
sudo bash /opt/freenetvpn-mini/scripts/show-clients.sh
```

Отдельно получить данные можно так:

```bash
# Полный WireGuard-профиль
sudo cat /opt/freenetvpn-mini/clients/wireguard/client1.conf

# Готовая VLESS-ссылка для импорта
sudo cat /opt/freenetvpn-mini/clients/vless/client1.txt

# Полный клиентский JSON для Xray
sudo cat /opt/freenetvpn-mini/clients/vless/client1.json
```

Чтобы сохранить WireGuard-профиль на локальный компьютер, выполните **на локальном компьютере**:

```bash
ssh <ssh-user>@ВАШ_СЕРВЕР 'sudo cat /opt/freenetvpn-mini/clients/wireguard/client1.conf' > client1.conf
chmod 600 client1.conf
```

Импортируйте `client1.conf` в официальное приложение WireGuard. VLESS-ссылку импортируйте в клиент с поддержкой **VLESS TCP + REALITY + Vision**. JSON использует локальный SOCKS5-прокси `127.0.0.1:1080`.

## Управление клиентами и ключами

В разделе **«Клиенты и подключения»** панели доступны следующие операции:

- **Создать ключи:** введите имя и выберите WireGuard или VLESS. Если оставить имя пустым, будет использовано `clientN`. Допустимы строчные `a-z`, цифры, `-` и `_`, максимум 32 символа.
- **Скачать:** отдельный `.conf` для каждого WireGuard-клиента, `.txt` и `.json` для VLESS.
- **Копировать:** скопировать VLESS-ссылку выбранного клиента.
- **Перевыпустить:** заменить только ключи выбранного клиента. Его старая конфигурация перестанет работать; остальные клиенты не изменятся.
- **Удалить:** удалить клиента из серверной конфигурации и удалить его файлы. Последнего клиента протокола удалить нельзя.

Каждый WireGuard-клиент получает отдельный адрес из `WG_ADDRESS`, а VLESS-клиент — отдельные UUID и short ID. После операции панель обновляет `/etc/wireguard/wg0.conf` или `/etc/xray/config.json` и перезапускает только соответствующий сервис. Можно создать до 100 клиентов на протокол.

При обновлении со старой версии существующий `client1`, серверные ключи REALITY, UUID и short ID сохраняются. Секреты не отправляются во внешние сервисы.

## Доступ к панели управления

Панель показывает состояние WG/VLESS, handshake и трафик WireGuard, версию Xray, свободное место и память. Через неё можно управлять клиентами, скачивать их файлы, копировать VLESS-ссылки и перезапускать VPN-сервисы.

Панель слушает **только `127.0.0.1:8080`**. Открывать порт 8080 в UFW или у провайдера не нужно.

### 1. Создайте SSH-туннель

Выполните на **локальном компьютере**, заменив `<ssh-user>` и `ВАШ_СЕРВЕР` на свои данные:

```bash
ssh -N -L 8080:127.0.0.1:8080 <ssh-user>@ВАШ_СЕРВЕР
```

Например:

```bash
ssh -N -L 8080:127.0.0.1:8080 root@203.0.113.10
```

Команда не откроет обычную SSH-сессию и будет оставаться запущенной — это нормально. Не закрывайте терминал, пока используете панель. Если SSH работает на нестандартном порту, добавьте `-p ПОРТ` после `ssh`.

### 2. Откройте панель

В браузере перейдите на [http://127.0.0.1:8080](http://127.0.0.1:8080) и введите:

- **Логин:** `admin`;
- **Пароль:** сгенерированный пароль из результата установки.

Если порт 8080 уже занят на локальном компьютере, используйте другой локальный порт, например:

```bash
ssh -N -L 18080:127.0.0.1:8080 <ssh-user>@ВАШ_СЕРВЕР
```

Тогда адрес панели будет `http://127.0.0.1:18080`.

### 3. Если пароль потерян

Подключитесь к серверу по SSH и выполните:

```bash
sudo python3 /opt/freenetvpn-mini/panel/server.py --reset-password
```

Команда выведет новый пароль. Перезапускать панель после этого не нужно.

Для завершения туннеля вернитесь в терминал с командой `ssh -N -L ...` и нажмите `Ctrl+C`. Пароль хранится как PBKDF2-SHA256-хеш. Панель использует Basic Authentication внутри SSH-туннеля, строгие security headers и проверку Origin для операций перезапуска. Публичный listener намеренно запрещён в коде.

Файлы подключений содержат приватные ключи. Передавайте их только по защищённому каналу и не публикуйте. Права на секреты и клиентские профили ограничены root.

## Обновление установленной версии

Команда загружает актуальный код и повторно применяет конфигурацию. Каталог `data`, файл `.env`, пароль панели и существующие клиенты сохраняются:

```bash
sudo bash -c 'set -e; f=$(mktemp); trap "rm -f -- \"$f\"" EXIT; curl -fsSL https://raw.githubusercontent.com/evdokimenkoiv/FreeNETvpn-mini/main/scripts/update.sh -o "$f"; bash "$f"'
```

После обновления закройте и заново откройте страницу панели или обновите её через `Ctrl+F5`.

## Проверка и обслуживание

```bash
sudo bash /opt/freenetvpn-mini/scripts/health.sh
systemctl status wg-quick@wg0 freenetvpn-xray freenetvpn-panel
journalctl -u freenetvpn-xray -u freenetvpn-panel -n 50 --no-pager
```

Основные настройки находятся в `/opt/freenetvpn-mini/.env`, секреты — в `data/state.json`. После изменения `.env` выполните `sudo bash /opt/freenetvpn-mini/install.sh`; клиентские файлы будут перегенерированы с теми же ключами. Для смены адреса сервера достаточно обновить `SERVER_HOST`. Ключи отдельных клиентов перевыпускаются через панель; не редактируйте отдельные поля `state.json` вручную.

Для резервной копии сохраните вне сервера каталоги `/opt/freenetvpn-mini/data`, `/opt/freenetvpn-mini/clients` и файл `.env`. Резервная копия содержит все VPN-секреты.

Поддерживается IPv4; IPv6-туннель и публичный веб-интерфейс намеренно не входят в mini. Автоматических обновлений Xray нет: закреплённая версия меняется вместе с кодом репозитория.
